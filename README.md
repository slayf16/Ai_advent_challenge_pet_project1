# Ai_advent_challenge_pet_project1

Простое веб-приложение для общения с DeepSeek. Интерфейс отправляет историю диалога во внутренний серверный маршрут, а тот обращается к DeepSeek API. API-ключ хранится только на сервере и не передаётся в браузер.

## Возможности

- диалог с моделью `deepseek-v4-flash`;
- отправка по Enter и перенос строки по Shift+Enter;
- отображение истории, процесса загрузки и понятных ошибок;
- создание нового диалога без перезагрузки страницы;
- адаптивный тёмный интерфейс;
- панель рядом с чатом: описание формата, лимит токенов и завершение по инструкции или стоп-строке;
- необязательные параметры и кнопка «Очистить параметры» для ответа без дополнительных условий;
- повтор последнего запроса с исходным контекстом и новыми параметрами для сравнения ответов;
- просмотр точного JSON последнего обращения к DeepSeek, включая системную инструкцию;
- пояснение, если ответ обрезан по лимиту токенов;
- серверная проверка формата и размера сообщений;
- интеграция WebMCP-инструмента `send_deepseek_message` для поддерживаемых окружений.

## Стек

- TypeScript, React 19;
- vinext, Vite и React Server Components;
- Tailwind CSS 4 и shadcn/ui;
- Cloudflare Workers / Wrangler;
- DeepSeek Chat Completions API.

Требуется Node.js `22.13.0` или новее.

Поток запроса:

```text
Браузер → POST /api/chat → DeepSeek API → /api/chat → браузер
```

Маршрут `app/api/chat/route.ts` добавляет системное сообщение только при заполненных параметрах, ограничивает историю 30 сообщениями и длину каждого сообщения 12 000 символами, устанавливает тайм-аут запроса и нормализует ошибки внешнего API.

Клиент отправляет последние 29 сообщений (14 пар и текущий вопрос). Кнопка «Повторить запрос» использует снимок исходного запроса: предыдущие варианты ответа не добавляются в его контекст. Обычное новое сообщение продолжает текущую историю. «Новый диалог» очищает историю и JSON, сохраняя выбранные параметры.

## Задание 2: управление ответом

1. Введите вопрос. При желании задайте справа формат, например «Нумерованный список из трёх пунктов»; пустое описание не добавляет требований к формату.
2. Можно указать максимум токенов от 1 до 4 096 или оставить поле пустым для лимита DeepSeek по умолчанию. Указанное число — жёсткий лимит API; токены не равны словам, ответ может быть обрезан.
3. Выберите «Без условия», явную инструкцию или стоп-строку, например `[END]`. Пустая или состоящая только из пробелов инструкция/стоп-строка также не добавляет условия завершения. Для заполненной стоп-строки сервер просит модель поставить маркер в конце и передаёт его в `stop` без изменения пробелов. API исключает маркер из ответа. Не используйте маркер, который может встретиться внутри нужного текста.
4. Отправьте сообщение, измените параметры и нажмите «Повторить запрос», чтобы сравнить ответы на тот же вопрос с тем же контекстом.

По умолчанию все поля пустые. Кнопка «Очистить параметры» возвращает это состояние, сохраняя чат. Когда все поля пустые, запрос содержит только `model`, `messages` и `stream: false`: без системной инструкции, `max_tokens`, `thinking` и `stop`. Действуют стандартные ограничения DeepSeek API. Каждый параметр можно задавать и очищать независимо от остальных.

Заполненное описание формата и инструкция завершения передаются в системном сообщении; их соблюдение зависит от модели. Это не принудительный JSON-режим. Только при заданном лимите токенов сервер задаёт `thinking: { "type": "disabled" }`, чтобы лимит относился к видимому ответу.

Под панелью отображается тело фактически переданного в `fetch` запроса, полученное от сервера после завершения попытки, с отступами для чтения. При изменении настроек этот снимок не меняется до следующей отправки. При ошибке внешнего API или сети JSON попытки остаётся доступен; при локальной валидации или отсутствии ключа запрос не выполняется и JSON не показывается. Снимок не подтверждает доставку при сетевой ошибке. Заголовок авторизации в него не входит.

Параметры API: [документация DeepSeek](https://api-docs.deepseek.com/api/create-chat-completion/).

## Локальный запуск

1. Клонируйте репозиторий и перейдите в него:

   ```bash
   git clone https://github.com/<ваш-логин>/Ai_advent_challenge_pet_project1.git
   cd Ai_advent_challenge_pet_project1
   ```

2. Установите зависимости:

   ```bash
   npm install
   ```

3. Создайте `.env.local` на основе примера:

   ```bash
   cp .env.example .env.local
   ```

   В Windows PowerShell используйте:

   ```powershell
   Copy-Item .env.example .env.local
   ```

4. Запишите в `.env.local` свой ключ DeepSeek:

   ```dotenv
   DEEPSEEK_API_KEY=your_real_deepseek_api_key
   ```

5. Запустите режим разработки:

   ```bash
   npm run dev
   ```

   Откройте адрес, указанный в терминале (обычно `http://localhost:3000`).

## Сборка и запуск production-версии

```bash
npm run build
npm start
```

Дополнительные команды:

```bash
npm run lint    # проверка кода
npm test        # проверки API без настоящих сетевых запросов и ключа
npm run format  # форматирование
```

## Безопасность

- Никогда не добавляйте настоящий API-ключ в исходный код, README, issue или commit.
- Не коммитьте `.env`, `.env.local` и другие `.env*`-файлы — они исключены через `.gitignore`.
- В репозитории должен оставаться только `.env.example` с фиктивным значением.
- При публикации задавайте `DEEPSEEK_API_KEY` как секрет или серверную переменную окружения на платформе хостинга.
- Если ключ случайно попал в Git, немедленно отзовите его в DeepSeek и создайте новый: удаления файла из последнего commit недостаточно.

## API приложения

`POST /api/chat` принимает JSON:

```json
{
  "messages": [{ "role": "user", "content": "Привет!" }],
  "settings": {
    "format": "Ответь нумерованным списком из трёх пунктов, без вступления.",
    "maxTokens": 512,
    "stopMode": "instruction",
    "stopInstruction": "Заверши ответ сразу после последнего пункта.",
    "stopSequence": "[END]"
  }
}
```

`settings` и все его поля необязательны. `{}` или отсутствие `settings` означают ответ без дополнительных условий. `format` и `stopInstruction` — строки до 2 000 символов, `stopSequence` — до 200; пустые строки и строки из пробелов не добавляют условий. `maxTokens` — целое число 1–4 096 либо `null` (пустое поле). `stopMode` принимает `none` (по умолчанию), `instruction` или `sequence`. Неактивное поле завершения не влияет на запрос.

Успешный ответ (поле `requestJson` ниже сокращено для примера):

```json
{
  "message": "Ответ модели",
  "model": "deepseek-v4-flash",
  "finishReason": "stop",
  "requestJson": "{...}"
}
```

`requestJson` содержит сериализованное тело обращения к DeepSeek: `model`, `messages`, `stream: false` и только выбранные дополнительные параметры. Системное сообщение появляется при наличии хотя бы одного условия. `finishReason: "length"` сообщает об обрезанном ответе. Ошибки после попытки обращения также возвращают `requestJson`; локальные ошибки — только `error`. Все ответы имеют `Cache-Control: no-store`.

Клиенту не требуется и не следует передавать `DEEPSEEK_API_KEY`: сервер читает его из переменной окружения и самостоятельно добавляет заголовок авторизации при запросе к `https://api.deepseek.com/chat/completions`.
